# BUG-0120 get_repo_map が全体の把握（主要なパッケージ・入口のモジュール）に向かない（能力ベンチの T01 で再現率 0.556）

- 報告: 2026-10-31 / 見た人: 親（能力測定の基準〈Mnemo の能力ベンチ〉の課題 T01）
- 見たことだけを書く（調査していない。調査は直す役の仕事）

## 実測（`main` = `b124359`、Mnemo の固定の写し、`get_repo_map` 既定）

- T01「リポジトリの地図（主要なパッケージと入口のモジュール）」: 再現率 0.556（期待 18 のうち 10）。挙げられなかったのは `src/mnemo/api`・`src/mnemo/tools`・`src/mnemo/agents`・`src/mnemo/bootstrap`・`src/mnemo/logic`・`src/mnemo/mcp` など 8 個。応答 1,471 トークン、20 秒（別の測りで `max_tokens=5000` のとき 20.25 秒）。
- 地図の 1 行目は最上位のディレクトリの件数だけ（`- src/ (N files), ...`）。2 段目以下のパッケージの一覧が無く、以降は被参照（fan_in）の多いファイルの骨格が並ぶ。

## 利用者（呼ぶ側の AI）として困ること

- 初めてのリポジトリで最初に知りたい「どんなパッケージがあり、入口はどこか」が出ない。中心のファイルの骨格は出るが、全体の形が分からない。
- 1 回の地図に 20 秒かかる（大きなリポジトリ）。

## 原因・直し方・確認（2026-10-31）

- 原因（全体の形が出ない）: 地図の先頭はトップレベルのディレクトリ別のファイル数の 1 行だけで、その後は被参照（PageRank）の多い
  ファイルの骨格が並ぶ作りだった。2 段目以下のパッケージの一覧と入口のモジュールを出す規則が無く、`src/mnemo/api`・`tools` のような
  呼ばれる側でないパッケージは PageRank が低いので骨格にも出なかった。
- 直し方（呼ぶ側の AI の使いやすさで決めた）: 新しい `tools/_overview.py` が、ファイルブロックの前の概観を組む（今までのトップレベルの行は残す）。
  - `- packages: src/mnemo/ (621 files), companions/ (175 files), …`: コードのパッケージの根。直下にコードが無く子が 1 つのディレクトリはつなぐ
    （`src/` → `src/mnemo/`）。隠しディレクトリ・文書とデータ（Tier 3）・図・圧縮済み（`lexical_fallback`）は数えない。重要度（スコアの和）順、10 件まで。
  - `- entry modules: src/mnemo/main.py, …`: `pyproject.toml` のスクリプトが指すモジュール、次に `main` / `__main__` / `app` / `cli` / `*_entry` を浅い順に 8 件まで。
  - `- src/mnemo/: src/mnemo/core/ (207), src/mnemo/agents/ (81), …`: 2 段目のサブパッケージをフルパス（`scope_paths` にそのまま渡せる）で、根の順・大きさ順に。
  - 大きさは 375 トークン（既定の予算 1500 の 1/4）までで `max_tokens` に依らない。比例させると予算を少し上げたときに概観が 1 項目伸びて後ろの
    ブロックが落ちる帯ができ、予算に対する単調性（§5.6 規則 5・BUG-0067）を破る（離散の行では避けられない）。予算が足りないときは先頭のレコードの
    縮退で、サブパッケージ → 入口の行を外してブロックを丸ごと残し、次にトップレベルとパッケージの 2 行を残してブロックを縮め、最後に 2 行も外す。
  - json は `packages[]`（`dir`・`file_count`・`line_count`・`children[]`）と `entry_modules[]` を足した（`tree[]` と同じく `max_tokens ÷ 10` に収まる分まで）。
- 原因（遅い）と直し方: `index/rank.file_symbol_ranks`（表示するファイルごとに呼ぶ）の問い合わせを SQLite が `_symbol_rank` の総なめから始めていて
  1 回 0.15〜0.22 秒だった（cProfile: Mnemo の写し 4,221 ファイルの索引で `max_tokens=5000` の地図 11.7 秒のうち 45 回・9.8 秒）。ファイル → シンボル →
  `_symbol_rank` の順に `CROSS JOIN` で固定し（同じ行を返す。1 回 0.002 秒）、同じ地図が 0.97 秒（`max_tokens=1500` は 0.80 秒）になった。残りは
  `repo_map_files`（全シンボルの窓関数）の約 0.46 秒。
- 仕様書 T-01 処理規約 3 に概観の規則・縮退の順・json の欄と理由を書き、出力例と json の表を直した。ツールの説明に概観を足した。
- 試験: 新しい `tests/unit/test_tools_overview.py`（根のつなぎ・文書と隠しの除外、2 段目のフルパスと大きさ順、`pyproject` のスクリプト → `*_entry` → 浅い順の入口、
  行の順と json、上限の中で 根 → 入口 → サブパッケージの順に入る、根の `+N more`、コードが無いとき）、`tests/contract/test_T01_repo_map.py` に
  F-POLY の概観（`packages: src/shop/ (10 files), web/src/ (2 files)`・`entry modules: web/src/app.ts`・`src/shop/: src/shop/models/ (4), …`・json）と
  予算 180〜900 で概観の行とファイルが減らない試験。BUG-0116 の試験の 260 は、パッケージの行を残して先頭のブロックのシグネチャを外す期待にした（予算の 9 割以上を使うのは同じ）。
- 能力ベンチ（Mnemo の固定の写し `d419cf0b`、`bench/capability/run.py --engines lucianke --only T01,T02`、出力は作業用の一時フォルダ。
  直す前は `ca95100` のソースの写しで同じ条件）: **T01 再現率 0.556 → 1.0**（期待 18 のうち 10 → 18。応答 1,471 → 1,476 トークン、冷えた 1 回目
  5.89 → 1.29 秒・温まった 2 回目 6.22 → 1.40 秒）。T02 F1 0.667 → 1.0（BUG-0121。応答 282 → 125 トークン）。
