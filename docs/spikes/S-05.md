# S-05 TypeScript の LSP（vtsls / typescript-language-server）の探索・起動・主要要求

- 実施日: 2026-10-29
- 環境: Windows 11 Home 10.0.26300 / Node v25.2.1 / Python 3.12.11（JSON-RPC クライアントは `spikes/s04_lsp/lsp_probe.py`）
- サーバー: `@vtsls/language-server` 0.3.0（`serverInfo` = vtsls 0.3.0。同梱 TypeScript 5.9.3）／ `typescript-language-server` 6.0.2（`serverInfo` なし）。TypeScript は npm の `typescript@7.0.2`（`lib/tsserver.js` が無い）と、別に入れた 6.0.3
- 判定: **合格**（両方で `definition` / `references` / `rename` が通る）。ただし診断の扱いに差があり、**既定は typescript-language-server を推奨**（設計書の想定は vtsls 既定）。

## 確かめたこと

起動（`node` + スクリプト直、`node_modules/.bin/*.cmd` 経由）→ `initialize`（`positionEncodings: ["utf-8","utf-16"]` を提示）→ `didOpen` → `publishDiagnostics` → `definition` / `references` / `hover` / `prepareRename` / `rename` / `codeAction`（quickfix・organizeImports・fixAll）/ `callHierarchy` → `didChange` → tsserver の所在の渡し方 → `shutdown` → `exit`。ウォーム後 10 回の中央値。通常の実行はすべて終了確認まで行った（`exit_code` 0、強制終了なし）。

### 診断の版・時系列（設計に効く差）

| 観測 | vtsls | tsls |
|---|---|---|
| `publishDiagnostics.version` | **無し** | **無し** |
| 診断の無いファイルを開く | **何も届かない**（`tsconfig.json` に空配列は届く） | 空配列が届く |
| エラーを足す（v2） | 515 ms で n=1 | 389 ms で n=1 |
| **エラーを消して元に戻す（v3）** | **n=1 のまま届く（古い診断）**。次の変更で n=0 になる。「無関係な編集で正常化」でも古い n=1 が届いた。3 回の別実行で再現 | 389 ms で n=0（常に最新） |
| 全エラーを消す（app.ts） | n=0 | n=0 |
| uri の形 | `file:///s%3A/work/...`（小文字ドライブ・`:` が `%3A`） | 同じ |
| 診断の `source` / 未使用の重大度 | `ts` / 2（警告） | `typescript` / 1（`noUnusedLocals` で error） |

### tsserver の所在

| 条件 | vtsls | tsls |
|---|---|---|
| 既定（ワークスペースに TypeScript が無い／7.x のみ） | 同梱の 5.9.3 を使う（設定不要） | **`initialize` が失敗**: `Could not find a valid TypeScript installation. Please ensure that the "typescript" dependency is installed in the workspace or that a valid tsserver.path is specified.`（npm の `typescript@7` には `lib/tsserver.js` が無い） |
| ワークスペースの `node_modules/typescript` | `workspace/configuration` の応答で `{"vtsls":{"autoUseWorkspaceTsdk":true}}` を返すと採用。**返さないと同梱を使う** | 自動で採用（ログ `Using Typescript version (workspace) 6.0.3`） |
| パスの明示 | `typescript.tsdk`（`lib` の絶対パス）は **`autoUseWorkspaceTsdk: true` と併せたときだけ**効く。単独・`initializationOptions`・`didChangeConfiguration` では無視された | `initializationOptions: {"tsserver": {"path": "<…>/typescript/lib/tsserver.js"}}` で採用（ログ `user-setting`） |

### 終了処理（Windows）

- `node <スクリプト>` を直接起動し、`shutdown` なしで親を `terminate` しても、tsserver の子は残らない（stdio が閉じて自分で終わる）。
- **`.bin/vtsls.cmd`（シム）経由で `cmd.exe` だけを殺すと、`node` が残る**（パイプを握り続け、`proc.wait()` も返らない）。強制終了は木ごと（`taskkill /T /F` か Job Object）にする。通常の `shutdown` → `exit` では残らない。
- `shutil.which("vtsls", path=<…>/.bin)` は `vtsls.CMD` を返す。`.bin` には `vtsls`（sh）・`vtsls.cmd`・`vtsls.ps1` が並ぶ。`.cmd` は `create_subprocess_exec` にそのまま渡して起動できた。

## 設計への反映

- **§7.5.1 表（TypeScript / JavaScript の行）**: 既定を `typescript-language-server --stdio`、代替を `vtsls --stdio` に入れ替える。理由: 診断が常に最新で空配列も届く、診断が約 110 ms 速い、`definition` の範囲が名前になる。vtsls は TypeScript を同梱するので、**tsserver が見つからないとき**（tsls の `initialize` 失敗）の代替にする。
- **探索順（サーバー）**: `LUCIANKE_LSP_TS_CMD` → `<root>/node_modules/.bin/typescript-language-server(.cmd)` → PATH（`shutil.which`）→ 同じ順で vtsls。
- **探索順（tsserver）**: 明示指定 → `<root>/node_modules/typescript/lib/tsserver.js`（存在確認。TypeScript 7 には無い）→ 無ければ vtsls へ切り替える。tsls へは `initializationOptions.tsserver.path`、vtsls へは `workspace/configuration` の応答で渡す（`LspServerDef` に `init_options` に加えて「設定の応答」を持たせる）。
- **§6.5 終了手順**: Windows のシム起動では強制終了を木ごとにする（または `node` とスクリプトを解決して直接起動）。
- **診断（§10 の `v_n` 照合）**: どちらも `version` を返さない。**publish を受けた＝現行とは言えない**（vtsls は古い内容を返す）。変更ごとの発行を数えて追い越しを検出する設計にする。クリーンなファイルに空配列が届かない vtsls に備え、「届かない＝0 件」とみなす猶予時間（設計値: 2 s）を持つ。
- **§7.5.1 `requests_m1`**: `rename` は `changes`（`documentChanges` に頼らない）。quickfix は `documentChanges`（tsls）／`changes`（vtsls）の両形を受ける。organizeImports は経路が違う（上表）ため、サーバー定義ごとに持つ。
- **OD-7 の改版は不要**（TS を best effort に格下げしない）。**未確認**: 開いていないファイルの診断（設計書 §10 の前提 S-4/S-5）。

## 使うコードの型

```python
# 起動コマンド: 候補を順に試し、最初に実行できたものを採る
def find_ts_server(root: Path, name: str) -> list[str] | None:
    exe = shutil.which(name, path=str(root / "node_modules" / ".bin")) or shutil.which(name)  # Windows は .CMD
    return [exe, "--stdio"] if exe else None

# tsls: tsserver の所在は initializationOptions で渡す（無ければ vtsls へ）
init = {"tsserver": {"path": str(root / "node_modules/typescript/lib/tsserver.js")}}
# vtsls: workspace/configuration（section "" の要求）への応答
cfg = {"vtsls": {"autoUseWorkspaceTsdk": True}}   # 絶対パスで渡すなら {"typescript": {"tsdk": "<lib>"}} も併せる

caps = {"general": {"positionEncodings": ["utf-8", "utf-16"]},
        "workspace": {"workspaceEdit": {"documentChanges": True}, "configuration": True, "applyEdit": True},
        "window": {"workDoneProgress": True}}   # + rootUri / workspaceFolders
```

サーバーからの要求への応答: `workspace/configuration`（vtsls は section `""`、tsls は `formattingOptions`。`{}` で可）、`window/workDoneProgress/create`、`client/registerCapability`、tsls の `workspace/applyEdit`（編集を受け取って `{"applied": true}`）。
