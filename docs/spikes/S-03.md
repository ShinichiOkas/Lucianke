## 結果（`run_astgrep.py`、すべて OK）

| 項目 | 結果 |
|---|---|
| 検索 | `SgRoot(src: str, "python").root().find_all(pattern="print($MSG)")` → `list[SgNode]`。`print($MSG)` は引数 1 個の呼び出しだけに一致（`print(1, 2)` は不一致）。`find_all` は設定辞書（`{"rule": ..., "constraints": ...}`）も取れる |
| メタ変数 | 単一: `node.get_match("MSG")`（無ければ `None`）。複数: `node.get_multiple_matches("ARGS")` は **区切りの `,` も 1 ノードとして含む**（`1 , 2` → `["1", ",", "2"]`）。0 個一致は `[]`（未定義名と区別できない） |

| 自前展開（`snippets.py`） | パターンから変数名を拾い、`$X` は `get_match` のテキスト、`$$$X` は先頭ノードの開始〜末尾ノードの終了の**ソース断片**（区切りと空白を保つ）で展開。複数行はインデントを挿入先に合わせてずらす。パターンに無い変数の参照は `TemplateError` |
| 実行結果 | Python: `print('a')` → `logger.info('a')`、`print(f'b {x}')` → `logger.info(f'b {x}')`、`foo(print(1, 2), 3)` は不変。TypeScript / TSX / JavaScript: `print(a)` → `logger.info(a)`、`function f() { print('x') }` → `{ logger.info('x') }`。`console.log($$$ARGS)` → `logger.info($$$ARGS)` も `'hi', a` を保って成功 |
| 入れ子 | `foo(foo(1))` に `foo($X)` は**外側と内側の両方**を返す。重なる `Edit` を `commit_edits` に渡すと落ちずに外側が勝つ（`bar`）が、`outermost()` で外側だけにして渡すのが安全 |

## 設計への反映

1. **§7.4.7（書き換え）**: 「書き換え API が無ければ自前展開」の条件のうち、`replace` と `commit_edits` は**ある**が、`replace` は展開しない。したがって `rewrite(match, template)` は自前の展開（`$X` と `$$$X`、複数行のインデント調整）で実装し、適用だけ `commit_edits` を使うか、`Match` の `start_index` / `end_index` で文字列を直接つなぐ。`Match.meta_vars` は `(start, end, text)`（コードポイント単位）で足りる。
2. **位置（ADR-14・§5.10）**: ast-grep の行列は 0 始まりのコードポイント単位で、Lucianke 内部と同じ。tree-sitter（バイト）とは別経路で、`structural.py` の出力にはそのまま使える。入力は `str`（UTF-8 のデコードが要る。不正な UTF-8 のファイルは書き換えを拒否する）。
3. **E_SYNTAX_INVALID**: 不正パターンは 0 件になるだけなので、①`RuntimeError`（単独ノードにならない）は `E_SYNTAX_INVALID` に、②**一致 0 件のときだけ** tree-sitter でパターンを解析して ERROR なら `details.hint` に「パターンが解析できない可能性」を付ける（ERROR だけで断定すると Rust・Java・C# の正しいパターンを誤判定する）。Go・C の式パターンは `context` / `selector` 形式で包む必要があるため、`LanguageSupport` に「パターン用の包み（context, selector）」を持たせる案（M2。T-12 の対象言語を決めるときに確定）。
4. **T-12 の重なり禁止**: 入れ子の一致は両方返るので、`outermost()` を必ず通してから hunk にする。
5. **§7.4.1 の登録表**: `structural` 検索の対象外は toml / xml / dtd / rst / sql / markdown_inline。`c_sharp` は ast-grep では `csharp`。未対応名で `SgRoot` を作ると `BaseException` 系のパニックと stderr 出力が出るので、**登録表（lang_id → ast-grep の言語名）で事前に弾く**。Kotlin・Swift は tree-sitter の PyPI 配布が無くても ast-grep は文法を内蔵しているため、構文パターン検索だけなら M1 でも使える（骨格・シンボルは別。要判断）。
6. **§7.4.7 の予算（`STRUCTURAL_SEARCH_MS` 5,000 ms）**: ast-grep は TreeCache の木を使えず自前で再解析する（約 10 ms / 2,000 行）。2,000 行のファイルなら 5 秒で約 400 ファイル。ファイル数が多い検索には、パターン中のリテラル（`print` など）を `bytes.find` で調べてから渡す前ふるいが効くはず（未測定・推奨）。GIL を解放しないのでスレッドプールでは速くならない（並列化するなら別プロセス）。
7. **§12.1 S-3 行**: 合格。「不合格時の代替（M2 まで保留）」は不要。

## 使うコードの型

`spikes/s03_astgrep/snippets.py` が完全版（`run_astgrep.py` で検証済み）。要点:

```python
from ast_grep_py import SgRoot

AST_GREP_LANG = {"python": "python", "typescript": "typescript", "tsx": "tsx", "javascript": "javascript",
                 "json": "json", "yaml": "yaml", "markdown": "markdown", "rust": "rust", "go": "go",
                 "c": "c", "cpp": "cpp", "c_sharp": "csharp",
                 "toml": None, "xml": None, "dtd": None, "rst": None, "sql": None, "markdown_inline": None}

def make_root(src: str, lang_id: str):                  # None の言語は事前に弾く（SgRoot は PanicException）
    name = AST_GREP_LANG.get(lang_id)
    if name is None: raise UnsupportedLanguage(lang_id)
    return SgRoot(src, name).root()

META_RE = re.compile(r"\$\$\$([A-Z_][A-Z0-9_]*)?|\$([A-Z_][A-Z0-9_]*)")   # $X / $$$X（_ 始まり・名前なしは捕捉しない）

# 検索: Match(start=(行, コードポイント列), end, start_index, end_index, text, single, multi, node)
def search(src, lang_id, pattern, constraints=None):    # pattern は str か {"context": ..., "selector": ...}
    root = make_root(src, lang_id)
    singles, multis = pattern_vars(pattern if isinstance(pattern, str) else pattern["context"])
    try:
        found = (root.find_all({"rule": {"pattern": pattern}, "constraints": constraints})
                 if constraints else root.find_all(pattern=pattern))
    except RuntimeError as e:                           # "cannot get matcher" -> E_SYNTAX_INVALID
        raise PatternError(str(e).splitlines()[0]) from e
    for n in found:
        r = n.range()                                   # r.start.line / .column / .index はコードポイント
        single = {k: n.get_match(k) for k in singles}   # SgNode | None（.text() と .range() が使える）
        multi = {}
        for k in multis:                                # $$$X: 先頭ノードの開始〜末尾ノードの終了を src から切り出す
            ns = n.get_multiple_matches(k)              # （区切りの , や空白を保つ。0 個なら None）
            multi[k] = src[ns[0].range().start.index : ns[-1].range().end.index] if ns else None
        yield r, n.text(), single, multi, n             # snippets.py の Match はこれを dataclass にしたもの

# 書き換え: 展開は自前、replace() は展開済み文字列を渡すだけ、適用は commit_edits
def rewrite(src, lang_id, pattern, template, constraints=None):
    ms = outermost(search(src, lang_id, pattern, constraints))      # 入れ子の内側を落とす
    edits = [m.node.replace(expand_template(template, m, src, pattern)) for m in ms]
    return ms[0].node.get_root().root().commit_edits(edits), len(ms)

# rewrite(PY_SRC, "python", "print($MSG)", "logger.info($MSG)")
#   "print('a')" -> "logger.info('a')"（引数 2 個の print(1, 2) は不変）
```

`expand_template`（複数行のインデント調整）、`outermost`、`pattern_hint`（0 件のときの警告）は `snippets.py` を参照。
