# S-02 tree-sitter 0.26 の API と文法の ABI 互換

- 実施日: 2026-10-29
- 環境: Windows 11 Home 10.0.26300 / Python 3.12.11 (MSC v.1944 64bit) / 48 論理コア / `tree-sitter` 0.26.0（`LANGUAGE_VERSION`=15、`MIN_COMPATIBLE_LANGUAGE_VERSION`=13）
- 文法: python 0.25.0 / typescript 0.23.2 / javascript 0.25.0 / json 0.24.8 / yaml 0.7.2 / toml 0.7.0 / xml 0.7.0 / markdown 0.5.4 / rust 0.24.2 / go 0.25.0 / c 0.24.2 / cpp 0.23.4 / c-sharp 0.23.5 / rst 0.2.0 / sql 0.3.11（`uv.lock` どおり）
- 判定: **合格**（対象 7 文法を含む全 18 言語で、読み込み・解析・タグ風クエリが通った）。ただし設計書 ADR-13 の前提 2 点（GIL、メモリ量）が実測と合わない。

## 確かめたこと

1. 基本 API（`Language` / `Parser` / `Node` / `Query` / `QueryCursor` / 増分解析 / ERROR・MISSING）
2. 18 言語の読み込み・サンプル解析・タグ風クエリ  3. ABI  4. 性能  5. スレッド  6. 非 ASCII の列

## 結果

### 1・6. API と位置（`run_api.py`、39 項目すべて OK）

| 項目 | 結果 |
|---|---|
| 読み込み | `Language(mod.language())`、`Parser(lang)`、`parser.parse(bytes)`。`str` は `TypeError`。`bytearray` / `memoryview` / `read_callback` も可 |
| 罠 | `parse(src, None)` は `TypeError`（`old_tree` に `None` を渡せない。省略する）。`captures(node, None)` も同様（述語は省略する） |
| 位置 | `start_byte` / `end_byte` はバイト。`start_point` / `end_point` は `Point(row, column)`（tuple 互換）。**column は行頭からのバイト数**。例: `s = 'あ😀' + x` の `x` はバイト 16・コードポイント 11・UTF-16 12 |
| 行の数え方 | `\n` だけが行区切り。CRLF では `\r` が行末に残る（文ノードは `\r` の手前で終わる）。単独の `\r` は改行にならない（LSP とは不一致）。UTF-8 BOM 付きは Python 文法が受理し、1 行目の列が 3 ずれる |
| `Node.text` | `bytes`。Tree が元のバイト列を保持する（`sys.getrefcount` が +1、コピーなし）。呼び出し側が変数を `del` しても読める |
| `Query` | 不存在のノード型は `QueryError`（`ValueError` の子）。`#eq?` `#match?` `#any-of?` は組込みで動く。独自述語は callable を渡せば動く |
| `QueryCursor` | `captures()` は `dict[str, list[Node]]`（`@name` と `@definition.*` の対応が失われる）。**`matches()` は `list[(pattern_index, dict[str, list[Node]])]`。タグは `matches()` で取る** |
| ERROR / MISSING | `Node.is_error` / `is_missing` / `has_error` で列挙できる（`error_spans`）。MISSING は幅 0（JS の `foo(1, 2` で欠けた `)`）。Python は構文が壊れると 1 個の大きな ERROR になり位置が粗い |
| 増分解析 | `tree.copy()` → `tree.edit(...)`（点はバイト列）→ `parser.parse(new, tree)`。結果は全解析と S 式が一致。`edit` は呼んだ木を直接書き換える |
| 不正な UTF-8 | 落ちない（ERROR になる） |

## 設計への反映

1. **§7.4.1 `grammar()` / 登録表**: 登録表から外す文法は無い（`status` の警告も不要）。`Language(getattr(importlib.import_module(m), fn)())`。`typescript`/`tsx`、`xml`/`dtd`、`markdown`/`markdown_inline` は 1 パッケージ 2 言語なので、`lang_id → (モジュール, 関数名)` の表で持つ（「使うコードの型」）。起動時検査は `MIN_COMPATIBLE_LANGUAGE_VERSION <= lang.abi_version <= LANGUAGE_VERSION` で足りる。ABI 14 の 9 言語（上の 5 パッケージ + yaml・rst）は ABI 15 版が出ていないので、`tree-sitter>=0.26,<0.27` に固定し、ロック更新時に `run_grammars.py` を回す（CI の煙試験にする）。
2. **§7.4.1 `queries()`**: パッケージ同梱の `TAGS_QUERY` を当てにしない（TS は JS との連結が要る、C# は `None`、データ形式・文書 9 言語は無い）。Lucianke が `.scm` を自前で持つ。`run_grammars.py` の `own_tags` 18 本がたたき台。
3. **§7.4.2 項目 1 と ADR-13（要改版）**: 「解析は常にスレッドプール」の理由づけが成り立たない。`parse(bytes)` は GIL を解放せず、スレッドプールは並列化せず（0.8〜0.98 倍）、プールで走らせても解析中はイベントループも止まる（2,000 行で 8 ms、5 MB で 750 ms）。推奨: **解析は常に `parse_with_deadline`（`read_callback` 16 KiB 刻み、速度は同等）を使う**。GIL を手放すので他スレッドの停止が最長約 20 ms に縮み、期限（`STRUCTURAL_SEARCH_MS` 相当）で打ち切れる。`progress_callback` は使用禁止。並列度が要るなら別プロセス（4 本で約 4 倍）で、§13 R-6 の「プロセスプールは M2 以降」の根拠になる。
4. **§7.4.2 項目 3・仕様書 §12.8（要確認）**: 構文木は**ソースの約 20〜26 倍のメモリ**を食う。`TREE_CACHE_MAX_BYTES`（512 MiB）をソースのバイト数で数えるなら実メモリは 10 GiB 超になる。推奨: 数える量を「ソース × 25」の推定木メモリにするか、上限を 32 MiB 程度（ソース換算）に下げる。
5. **§7.4.2 項目 1 の Parser 持ち方**: スレッドごと・言語ごとに 1 個（現行どおり）。共有しても壊れなかったのは GIL 直列化のおかげにすぎず、当てにしない。`Language` / `Query` / `Tree` / `Node` はスレッド間で共有してよい（`QueryCursor` は呼び出しごとに作る）。
6. **§7.4.2 項目 6（増分解析は MAY のまま）**: 全解析が 8 ms なので M1 は不要。やるなら `tree.copy()` してから `edit`（破壊的）。`Node.text` は Tree がソースを保持するので ADR-13 の「バイト列が無いとテキストを取れない」は緩むが、`line_index` のため `ParsedFile.source` は残す。
7. **§7.4.2 項目 5・§7.7.4**: `error_ranges()` は `error_spans`（「使うコードの型」）。Python は構文が壊れると位置の粗い 1 個の ERROR になるため、T-10 の構文検証は ERROR / MISSING の**個数の前後比較**を主に、位置は参考にする。
8. **ADR-14・§5.10**: tree-sitter の列は**バイト**。コードポイント列への変換を `syntax` の出口（`Range` を作る 1 か所）に置く。`LineIndex` は `\n` だけで行を切る（tree-sitter と一致させる）。LSP との境界でだけ単独 `\r` と BOM の扱いを合わせる（BOM は 1 行目の開始オフセットで除外するか、正規形で除く。§10 の正規化規則と整合を確認）。
9. **§12.1 S-2 行**: 合格。「対象 7 文法」を「18 言語」に広げて記録できる。S-3 は別紙。

## 使うコードの型

`spikes/s02_treesitter/snippets.py` が完全版（`run_api.py` / `run_perf.py` で検証済み）。要点:

```python
# 言語の読み込み表（lang_id -> (import 名, 関数の実名)）。Language は共有してよい
LANGUAGES = {"python": ("tree_sitter_python", "language"),
             "typescript": ("tree_sitter_typescript", "language_typescript"),
             "tsx": ("tree_sitter_typescript", "language_tsx"),
             "javascript": ("tree_sitter_javascript", "language"),
             "json": ("tree_sitter_json", "language"), "yaml": ("tree_sitter_yaml", "language"),
             "toml": ("tree_sitter_toml", "language"),
             "xml": ("tree_sitter_xml", "language_xml"), "dtd": ("tree_sitter_xml", "language_dtd"),
             "markdown": ("tree_sitter_markdown", "language"),
             "markdown_inline": ("tree_sitter_markdown", "inline_language"),
             "rust": ("tree_sitter_rust", "language"), "go": ("tree_sitter_go", "language"),
             "c": ("tree_sitter_c", "language"), "cpp": ("tree_sitter_cpp", "language"),
             "c_sharp": ("tree_sitter_c_sharp", "language"), "rst": ("tree_sitter_rst", "language"),
             "sql": ("tree_sitter_sql", "language")}

@functools.cache
def get_language(lang_id):                       # 失敗は例外のまま上げ、登録表から外す
    mod, fn = LANGUAGES[lang_id]
    return Language(getattr(importlib.import_module(mod), fn)())

# Parser はスレッドごと・言語ごとに 1 個
class ParserPool:
    def __init__(self): self._tl = threading.local()
    def parser(self, lang_id):
        d = self._tl.__dict__.setdefault("parsers", {})
        return d.get(lang_id) or d.setdefault(lang_id, Parser(get_language(lang_id)))

# 期限つき解析: read_callback が期限後に b"" を返す。GIL も手放す。例外送出・progress_callback は使わない
def parse_with_deadline(parser, source: bytes, seconds, chunk=16 * 1024):
    t_end, flag = time.perf_counter() + seconds, [False]
    def read(offset, _pt):
        if flag[0] or time.perf_counter() > t_end: flag[0] = True; return b""
        return source[offset:offset + chunk]
    return parser.parse(read), flag[0]          # timed_out なら木は捨てる

# タグ: matches() を使い、@name と @definition.* を同じ一致から取る
def run_tags(lang_id, query_src, tree):
    q = get_query(lang_id, query_src)            # @functools.cache した Query(language, src)
    for _i, caps in QueryCursor(q).matches(tree.root_node):
        name = (caps.get("name") or [None])[0]
        for cap, nodes in caps.items():
            if cap.startswith(("definition.", "reference.")):
                for n in nodes: yield cap, name and name.text.decode(), n

# ERROR / MISSING の列挙（重ならない。ERROR の中へは降りない）
def error_spans(root):
    out, stack = [], [root]
    while stack:
        n = stack.pop()
        if n.is_error or n.is_missing:
            out.append((n.type, n.is_missing, n.start_byte, n.end_byte, tuple(n.start_point), tuple(n.end_point)))
        elif n.has_error:
            stack.extend(reversed(n.children))
    return sorted(out, key=lambda e: e[2])

# バイト列 -> 行・コードポイント列・UTF-16 列（行は b"\n" だけで切る）
class LineIndex:
    def __init__(self, src: bytes):
        self.src, self.starts = src, [0] + [i + 1 for i, b in enumerate(src) if b == 10]   # 実装は find ループが速い
    def offset_to_point(self, off):
        row = bisect_right(self.starts, off) - 1; return row, off - self.starts[row]
    def byte_col_to_cp(self, row, byte_col):
        p = self.src[self.starts[row]:self.starts[row] + byte_col]
        return byte_col if p.isascii() else len(p.decode("utf-8", "replace"))
    def byte_col_to_utf16(self, row, byte_col):
        p = self.src[self.starts[row]:self.starts[row] + byte_col]
        return byte_col if p.isascii() else len(p.decode("utf-8", "replace").encode("utf-16-le")) // 2
```

逆変換（`cp_col_to_byte`、`utf16_col_to_byte`）は `snippets.py` を参照。タグ風クエリの例（Python）: `(function_definition name: (identifier) @name) @definition.function`。
