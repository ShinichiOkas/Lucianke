# S-1 MCP SDK の低水準 API とストリーム隔離

**判定: 合格**（1〜4 すべて可能。SDK クライアントから往復できる）。ADR-2 は変更不要、ADR-3 は結論を維持して文言を直す。

実施日: 2026-10-29 / OS: Windows 11 Home 10.0.26300 / CPU: AMD Ryzen Threadripper 3960X（24C/48T）、RAM 64 GB / CPython 3.12.11（uv 管理）/ mcp 2.3.0・mcp-types 2.3.0 / pydantic 2.14.1 / anyio 4.15.1。計測中、ほかの役のプロセスが同機で並行して動いていた。

## 確かめたこと

設計書 §12.1 の S-1 の 5 点。(1) `tools/list` に自前の JSON Schema（`additionalProperties: false` 込み）をそのまま返せるか。(2) `tools/call` の結果に `content`・`structuredContent`・`isError: true` を例外なしで載せられるか。(3) サーバー側から `roots/list` を要求し、`roots/list_changed` を受けられるか。(4) 退避 fd から作ったストリームをトランスポートに渡し、ツール内の `print` / `os.write(1, …)` などが本物の stdout に出ないか（外から stdout を記録して検査）。(5) HTTP 系依存の import とコールドスタート。生の JSON-RPC 行（SDK を通さない）と SDK クライアントの両方で見た。

## 結果

| # | 項目 | 判定 | 実測・所見 |
|---|---|---|---|
| 1 | 自前スキーマの素通し | 合格 | `inputSchema` が送った dict と完全一致（生の行・SDK クライアント・2026-07-28 の 3 経路）。pydantic `model_json_schema()` の `additionalProperties:false`・`anyOf`・`default:null`・`enum`・`minimum` も欠落なし。**SDK は引数をスキーマで検証しない**（`additionalProperties:false` を破る引数もハンドラに届く） |

**3 roots**
- 2025-11-25 以前のハンドシェイク版（いまのホストの版）: `notifications/initialized` のハンドラ内で `await ctx.session.list_roots()` が成功。`notifications/roots/list_changed` は `add_notification_handler` で受けて再取得できた。ツール呼び出し中の要求も可。クライアントが roots 能力を宣言していなければ `ctx.session.client_capabilities.roots is None` で分かる（要求するとエラー）。**`initialize` の処理中に要求を待つとデッドロック**（SDK ドキュメントの警告どおり）。通知ハンドラは別タスクなので待てる。
- 2026-07-28（SDK の `Client(mode="auto")` は `server/discover` で自動的にこちらを選ぶ）: `initialized` と `roots/list_changed` が仕様から消え、サーバー起点の `roots/list` は `NoBackChannelError`。代わりに `tools/call` の結果へ `InputRequiredResult(input_requests={"roots": ListRootsRequest()})` を載せ、クライアントが再呼び出しする方式で取得できた。SDK 2.3 は roots を非推奨（SEP-2577、呼ぶたび `MCPDeprecationWarning`）。

**4 fd 退避**（ツール内で `print`・`os.write(1)`・`sys.__stdout__`・UCRT `puts`・`WriteFile(GetStdHandle)`・stdout 継承の子プロセスの 6 経路を実行し、stdout を生バイトで記録）

| モード | stdout | 所見 |
|---|---|---|
| manual（ADR-3 + 明示ストリーム） | 純粋（全行 JSON-RPC、LF のみ） | 6 経路すべて stderr へ。子プロセスの stdin 読取は 0 バイト（fd 0 を NUL にした効果） |
| sdk（引数なし `stdio_server()`） | 純粋 | SDK 2.3 が同じ退避を自前でやる。ただし**行末が CRLF**、かつ退避は呼んだ時点（import 後）から |
| manual-nohandle（`SetStdHandle` なし） | 純粋 | CPython 3.12+UCRT の `dup2` が Win32 標準ハンドルも付け替える（`GetStdHandle(OUT)` が 212→444 になり `get_osfhandle(1)` と一致）。`SetStdHandle` は不要 |
| naive（手動退避 + 引数なし `stdio_server()`） | 応答 0 行 | fd 0 が NUL になっているため SDK が入力 EOF と見て即終了。**併用不可** |
| none（退避なし。対照） | 汚染 | `junk` が JSON-RPC の行に混ざる。検査に歯があることの確認 |

stdin を閉じると 117〜154 ms で終了コード 0（ADR-16・§6.5 の EOF 終了）。

**5 HTTP 系依存**
- `mcp` 2.3.0 の `Requires-Dist` は starlette・uvicorn・httpx2・sse-starlette・python-multipart・pyjwt[crypto]・opentelemetry-api・jsonschema・pywin32（win32）が**無条件**。extras は `cli`・`rich` だけ。**extras では外せない**。
- `mcp/__init__` が client・streamable_http まで import するため、stdio だけでも starlette・uvicorn・httpx2・sse_starlette・python_multipart・cryptography・opentelemetry・win32api がロードされる（`jwt`・`jsonschema`・`h11`・`httpcore2` は未ロード）。
- import 全体は約 890 ms（`-X importtime`）: mcp_types 約 440（3 版のワイヤモデル生成）、pydantic 約 120、starlette 約 95、sse_starlette 約 70、uvicorn 約 65、httpx2 約 45（累積。重なりあり）。
- **コールドスタート**（プロセス起動 → `initialize` 応答、n=7、ファイルキャッシュ温）: 本サーバー **中央値 980 ms**（959〜1030）、SDK Client 経由 1041 ms。素の venv の `python -c pass` は 57 ms、`uv run --frozen` 経由は 104 ms。
- 遅延 import の実験（`--stub-http` で HTTP 系 9 パッケージを空スタブに）: stdio 経路は最後まで動き、起動は 980 → 793 ms（−190 ms、−19%）。残りは mcp_types と pydantic で SDK 内部。**避けられるが SDK 内部の import 構造への依存が強いので採用しない**ことを推奨（下記）。

## 設計への反映

- **ADR-2: 変更不要。** 追記する事実: (a) v2 の低水準 API は `Server(name, on_list_tools=…, on_call_tool=…)` のコンストラクタ引数方式（v1 のデコレータではない）で、ハンドラは `(ctx, params)`。(b) SDK は引数を検証せず、漏れた例外は `code=0` のエラーにする → 検証と例外捕捉は §7.1.2 のパイプラインが全責任を持つ（設計どおり）。(c) `Server.middleware` は SDK 側が暫定 API と明記しているので製品コードでは使わない（本スパイクは計測にだけ使用）。`timing_ms` は §7.1.2 で自前計測。(d) 「SDK の版は固定する」の実行として `pyproject.toml` の `mcp>=2.3,<3` を `mcp>=2.3,<2.4` に絞る。
- **ADR-3: 結論は維持、文言を直す。** 「バイナリストリームを渡す」→ SDK が受けるのは `anyio.AsyncFile[str]`。退避 fd を `io.TextIOWrapper(os.fdopen(fd, "wb", closefd=False), encoding="utf-8", newline="\n")` で包み、`anyio.wrap_file` して `stdio_server(stdin=…, stdout=…)` に**明示的に**渡す（`newline="\n"` を忘れると Windows で CRLF）。代替案（`sys.stdout` を退避 fd のラッパに戻す）は不要。追記: fd 0 も NUL に差し替える（子が入力を横取りしない）／手動退避のあとに引数なしの `stdio_server()` を呼ばない／`SetStdHandle` は不要。仕様書 §12.1 の 2・3 にも stdin の隔離を足す。
- **§6.5 起動順 7・仕様書 §5.1:** `roots/list` は `initialize` の後（`notifications/initialized` ハンドラ内、タイムアウト 5 s）で要求する。ホストが roots 能力を宣言しない場合と 2026-07-28 では走らない（`list_changed` も来ない）ので、「取れなければ cwd と T-00 `set_roots`」を SHOULD から前提に格上げし、起動順 7 を「取れたら」に直す。2026-07-28 の `InputRequiredResult` 方式は、ホストが 2026-07-28 を話し始めた時点で M2 以降の課題として扱う。
- **仕様書 §5.1 と設計 §7.1.2 の食い違い（方針判断・推奨つき）:** 前者は「スキーマ違反の引数は JSON-RPC エラー」、後者は「検証失敗 → `E_INVALID_ARGUMENT`（isError）」。推奨は後者に揃える（エージェントが自己修正できる。SDK は引数を検証しないので実装はどちらも可能）。仕様書 §5.1 から「スキーマ違反の引数」を削る。
- **付録 A.3・R-2:** R-2 は S-1 合格で解消。コールドスタート約 1.0 s（本機）を A.3 に記録。遅延 import は −190 ms と効果が小さく SDK 内部依存なので不採用。ホストの MCP 起動待ちは通常数十秒で、1 s は許容。重くなったら SDK 側への提案を先に検討する。
- **§12.1 の S-1 行:** 「合格」に改版。

## 使うコードの型

全体は `spikes/s01_mcp/minimal_server.py`（`probe_minimal.py` で動作確認済み）。要点だけ抜粋する。

```python
# 1. 最初の 1 バイトの前（標準ライブラリだけ import）
import io, os, sys
def bootstrap_io() -> tuple[int, int]:
    real_out, real_in = os.dup(1), os.dup(0)   # 退避（非継承）
    os.dup2(2, 1)                              # print / os.write / C / 子プロセスの fd 1 は stderr へ
    nul = os.open(os.devnull, os.O_RDONLY); os.dup2(nul, 0); os.close(nul)   # 子に入力を渡さない
    sys.stdout = sys.stderr
    return real_in, real_out
REAL_IN, REAL_OUT = bootstrap_io()

# 2. 重い import はこの後
import anyio
from mcp import types
from mcp.server import Server, ServerRequestContext
from mcp.server.stdio import stdio_server
from mcp.shared.exceptions import MCPError

# 3. tools/list: 引数モデル（extra="forbid"）のスキーマをそのまま返す
async def on_list_tools(ctx: ServerRequestContext, params: types.PaginatedRequestParams | None):
    return types.ListToolsResult(tools=[
        types.Tool(name=n, description=d, input_schema=model.model_json_schema()) for n, d, model in SPECS])

# 4. tools/call: 通常の失敗は isError:true の結果。例外を外へ出さない。未知ツール名だけ MCPError
async def on_call_tool(ctx: ServerRequestContext, params: types.CallToolRequestParams):
    spec = REGISTRY.get(params.name)
    if spec is None:
        raise MCPError(code=types.INVALID_PARAMS, message=f"unknown tool: {params.name}")
    try:
        text, data = await spec.run(spec.model.model_validate(params.arguments or {}))
        return types.CallToolResult(content=[types.TextContent(type="text", text=text)],
                                    structured_content=data, is_error=False)
    except Exception as exc:                   # ValidationError も LuciankeError もここで envelope 化
        return types.CallToolResult(content=[types.TextContent(type="text", text=f"# {params.name} error …")],
                                    structured_content={"ok": False, "error": {"code": "E_INTERNAL"}}, is_error=True)

# 5. roots: initialized の後に要求。能力が無ければ要求しない。失敗しても動き続ける
async def on_initialized(ctx: ServerRequestContext, params: types.NotificationParams):
    caps = ctx.session.client_capabilities
    if caps is not None and caps.roots is not None:
        with anyio.fail_after(5):
            res = await ctx.session.list_roots()           # MCPDeprecationWarning は warnings で止める
        set_roots([str(r.uri) for r in res.roots])

server = Server("lucianke", version=VERSION, on_list_tools=on_list_tools, on_call_tool=on_call_tool)
server.add_notification_handler("notifications/initialized", types.NotificationParams, on_initialized)
server.add_notification_handler("notifications/roots/list_changed", types.NotificationParams, on_initialized)

# 6. 退避 fd のストリームを明示的に渡す（引数なしの stdio_server() は呼ばない）
async def main() -> None:
    stdin = io.TextIOWrapper(os.fdopen(REAL_IN, "rb", closefd=False), encoding="utf-8", errors="replace", newline="\n")
    stdout = io.TextIOWrapper(os.fdopen(REAL_OUT, "wb", closefd=False), encoding="utf-8", newline="\n")
    async with stdio_server(stdin=anyio.wrap_file(stdin), stdout=anyio.wrap_file(stdout)) as (read, write):
        await server.run(read, write, server.create_initialization_options())   # stdin の EOF で戻る
anyio.run(main)
```
